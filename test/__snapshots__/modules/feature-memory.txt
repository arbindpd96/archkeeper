##### feature-memory on examples/ts-app
=== .claude/skills/handoff/SKILL.md (owned, feature-memory)
---
name: handoff
description: Save this session's progress to the active feature's MEMORY.md so the next session resumes where this one stopped. Use before ending a session or compacting, or when a hook asks for a memory update.
---

Save this session's progress in the active feature's memory.

1. Find the active feature. It is the one named in `.acmekit/local/active-feature` when its `docs/features/<name>/MEMORY.md` says `Status: in progress`. Otherwise it is the only feature MEMORY.md that says so, leaving out folders whose names start with `_`, such as `docs/features/_template/`. If several say so, ask which one. If none does, offer `/new-feature <name>` and stop.
2. Read the file fully, then update it:
   - **Done**: tick what is finished, add new finished items as `- [x]` and keep open ones as `- [ ]`.
   - **Next step**: the single exact next action, naming the file, function or command, so a new session starts without asking.
   - **Decisions**: append each decision made this session as `- YYYY-MM-DD: <decision>. Why: <reason>.` Never change or drop an earlier one.
   - **Gotchas / don't try again**: what failed and why. If others could hit it too, add it to `docs/mistakes.md` as well.
   - **Open questions**: add new ones and remove the ones answered.
3. Keep the file at 80 lines or fewer by merging old Done items into one line each.
4. When the goal is met, set `Status: done`.
5. Show the user three lines: what was done, what is next, and any open question.
=== .claude/skills/new-feature/SKILL.md (owned, feature-memory)
---
name: new-feature
description: Start a feature with its own MEMORY.md, copied from the template, and make it the active feature.
disable-model-invocation: true
---

Start the feature named in `$ARGUMENTS`. If no name was given, ask for one.

1. Turn the name into kebab-case: lowercase letters, digits and single hyphens. If `docs/features/<name>/MEMORY.md` already exists, read it fully and resume that feature instead: set `Status: in progress` if it says otherwise, then go to step 4.
2. Ask the user what "done" means for this feature, in one or two lines, unless the request already says. If the current git branch is the default branch, offer to create a branch for the feature first.
3. Copy `docs/features/_template/MEMORY.md` to `docs/features/<name>/MEMORY.md`. Fill in the title (`# Feature: <name>`), `Status: in progress | Branch: <branch>` with the current git branch, the **Goal**, and the first concrete action under **Next step**. If the template is missing, write its sections yourself: Goal, Decisions (never undo without asking), Done, Next step, Gotchas / don't try again, and Open questions.
4. Make it the active feature: write `<name>` as the only line of `.acmekit/local/active-feature`. That folder is never committed, so if `.acmekit/local/.gitignore` is missing, write it first with the single line `*`.
5. Search the codebase for code this feature should reuse, and note it under **Next step** or **Open questions**.
6. Tell the user the goal, the branch and the next step.

=== AGENTS.md (blocks, base, block agent-rules)
Rules for AI coding agents, such as Claude Code, Codex, Cursor, Gemini CLI and Copilot, in this repository.

## Principles

1. **Think before coding.** State your assumptions. When a request is ambiguous, offer options or ask.
2. **Simplicity first.** Write the least code that solves the problem. No speculative features or abstractions.
3. **Surgical changes.** Touch only what the task needs. Never refactor unrelated working code.
4. **Goal-driven.** Define what "done" means, such as the tests passing, and verify it yourself before you report.

## Before creating anything new

1. Search the codebase for code that already does the job.
2. Reuse or extend it. Never duplicate it.

=== AGENTS.md (blocks, feature-memory, block feature-memory)
## Feature memory

Each feature keeps its working memory in `docs/features/<feature>/MEMORY.md`: the goal, decisions, progress and next step, so any session can resume it.

- Before changing code, read the active feature's MEMORY.md fully. If you do not know which feature is active, ask, and offer `/new-feature <name>` to start one.
- After an important decision, append it to **Decisions** with the date and the reason.
- Before ending a session, or when the context grows large, update **Done** and **Next step** (`/handoff` does both).
- Never contradict a recorded decision without asking the user first.
- Record approaches that failed in `docs/mistakes.md`, so nobody tries them again.

## Claude Code

- AGENTS.md holds the rules every AI tool shares: change shared rules there.
- Keep personal notes in CLAUDE.local.md, which git ignores.
- Claude Code reads .claude/settings.json and its hooks at startup, so restart it after changing them.

name: adr
description: Record an architecture decision as a numbered ADR in docs/adr/ and add it to docs/decisions.md.
disable-model-invocation: true
---

Record the decision `$ARGUMENTS` as an ADR. If no title was given, ask for one.

1. Take the highest number in `docs/adr/` and add one, written with four digits: the first ADR after `0000-template.md` is `0001`.
2. Copy `docs/adr/0000-template.md` to `docs/adr/<NNNN>-<title>.md`, with the title in kebab-case: lowercase letters, digits and single hyphens. Fill in every field and section from the conversation, and ask the user for anything missing. Set `Status: accepted` only when the user has agreed to the decision; otherwise `proposed`.
3. If it replaces an earlier ADR, set that ADR's status, and the status in its row of `docs/decisions.md`, to `superseded by ADR-<NNNN>`.
4. Add a row for it to the table in `docs/decisions.md`: the number linked to the file, the decision in one line, its status and its date.
5. Tell the user the new file's path and the decision in one line.
=== .claude/skills/why/SKILL.md (owned, knowledge)
---
name: why
description: Explain why the project is the way it is from its recorded decisions, citing each source by path and line. Use when someone asks why something was chosen, or before changing an established pattern.
---

Answer "why $ARGUMENTS?" from the project's records only. If no topic was given, ask for one.

1. Search these in order, skipping any that do not exist:
   - `docs/decisions.md` and the ADRs in `docs/adr/`
   - the **Decisions** sections of `docs/features/*/MEMORY.md`
   - `docs/mistakes.md`
2. If they do not answer it, search the commit history for one keyword at a time, a single word in single quotes: `git log --grep='<keyword>' -i --oneline`, trying a synonym or two.
3. Answer in two to five sentences. Cite each source as `path:line`, or a commit by its short hash.
4. If nothing is recorded, say so plainly instead of guessing a reason, and offer to record the answer with `/adr <title>` once the user decides.

=== AGENTS.md (blocks, base, block agent-rules)
Rules for AI coding agents, such as Claude Code, Codex, Cursor, Gemini CLI and Copilot, in this repository.

## Principles

1. **Think before coding.** State your assumptions. When a request is ambiguous, offer options or ask.
2. **Simplicity first.** Write the least code that solves the problem. No speculative features or abstractions.
3. **Surgical changes.** Touch only what the task needs. Never refactor unrelated working code.
4. **Goal-driven.** Define what "done" means, such as the tests passing, and verify it yourself before you report.

## Before creating anything new

1. Search the codebase for code that already does the job.
2. Reuse or extend it. Never duplicate it.

## Commands

| Command | What it does |
| --- | --- |
| `npm run build` | Build |
| `npm run test` | Run the tests |
| `npm run lint` | Lint |
| `npm run format` | Format |
=== AGENTS.md (blocks, knowledge, block knowledge)
## Decisions

`docs/decisions.md` lists the project's long-term decisions, each recorded as an ADR in `docs/adr/`. `docs/glossary.md` defines the project's terms.

- Before changing an established pattern, find out why it is so (`/why <topic>`).
- Never contradict an accepted ADR without asking the user first. To change one, record a new ADR that supersedes it (`/adr <title>`).
- Use the glossary's terms, and add one when a new term starts to matter.

## Gotchas / don't try again

- In this sandbox, run npm with `npm_config_cache` in a writable temp folder, or `test/check-package.test.ts` fails with EPERM.
- Never run `rm`, `git clean`, `git restore` or `git stash`; leave cleanup to the tools that own a folder.
- vitest 5: put the file filters first and `--update` last, since `-u` swallows the next argument.
- Real hook bundles use the real `BRAND`, init tests the test brand: a test that runs a real bundle in a project init set up writes `${BRAND.stateDir}/config.json` itself. `KIT` from `test/init-helpers.ts` holds stand-in bundles; anything that runs an installed hook uses `readKit(REPO_ROOT)`.
- Run `npm run package -- --update` after adding a published file: each hook bundle, module template and `modules/compose.json`.
- `check-brand` refuses the product slug outside `docs/`, root Markdown and `brand.ts`, comments and `modules/` included: write `{{brand.*}}` in templates and `<state dir>` in comments.
- A Markdown table cell wider than its column makes Prettier re-pad the whole table (the architecture map, the decision log): keep new cells within the column.
- A commit header over 100 characters fails commitlint after lint-staged has run: count it first.
- A test that puts a Windows path into a bash command single-quotes it and takes it from `realpathSync.native`.
- `src/cli/init.ts` is at 297 raw lines, about 263 of the 300 that lint counts without blank lines and comments, and `init-answers.ts` at 229: put new init logic in new files, as `init-stop-check.ts`, `init-compose.ts`, `init-config-commands.ts` and `init-sandbox.ts` are; `src/cli/init-tools.ts` settles the config and modules.
- The format-on-edit bundle is 29,982 of its 30,000 bytes after review round 7, 18 left: anything added to the runtime it bundles (`launch`, `io`, `project`, `state`, `options`, `tools`, `project-tools`, `env-files`) grows it, so measure with `npm run build` before committing. rolldown prints each array element of three or more on its own line, so word lists split at load time are smaller.
- A PostToolUse hook's exit 2 carries stderr alone, never JSON: a `systemMessage` waits for a run that reports nothing.
- CI tapes answer no prompt; each GIF fits its cap (20 s, 30 s for hero and live) and each screen 1100×560: 23 rows of 100 columns (cells 10.3 px wide, measured in a frame of `init.gif`), and the shell's prompt takes a row after the command's output. A line that wraps splits any `Wait+Screen` text across two rows, and the wait never matches.
- Partial staging (`git add -p`) is interactive and unavailable: when two commits' changes share a file such as `docs/architecture.md`, edit it in commit order, and verify an earlier commit alone from `git archive <sha> | tar -x -C "$TMPDIR/x"` with `node_modules` linked in.
- lint-staged backs up and restores unstaged changes itself on each commit; that is not a forbidden `git stash`.
- `npx tsdown` alone writes no `dist/THIRD_PARTY_LICENSES.md`, so `npm run package -- --update` after it drops that line from `scripts/package-files.txt`: build with `npm run build` first.
- The stop-check bundle is 29,978 of its 30,000 bytes after review round 7, 22 left: anything added to it, or to the runtime it bundles (`launch`, `io`, `project`, `state`, `options`, `tools`, `project-tools`, `git`, `git-status`, `work-files`), needs bytes found elsewhere. Each lazily loaded module costs about 150 bytes of `//#region` markers and init wrapper.
- An interactive init on full asks the stop-check question after the preset, so a test that answered `['full', true]` now answers `['full', false, true]`.
- An interactive init asks the compose select right after the preset while the config has no `compose` and `--with` is absent, so a test that answered `['medium', true]` now answers `['medium', 'no', true]`; a config that holds `compose` skips it (`configWith` in `test/init-opt-out.test.ts`).
- A commit body line that starts with a word and a colon, such as `them: …`, reads to commitlint as a footer and warns `footer-leading-blank`.
- Files a script edits skip the editor hook's Prettier: run `npx prettier --write` on them before `npm run check`.
- The editor hook lints after each Edit, so an import or constant a later Edit of the same change adds shows as an error from the earlier one: lint the file again before fixing anything.
- A new RegExp built from a template at load stays in every bundle that imports its module, used or not, since it may throw: build it where it is used.
- A hook module that imports a helper from a runtime module it did not import before also calls that module's `init_*()`: `slashed()` cost the stop check 26 bytes, not 9.
- An interactive init asks "Continue, letting the hooks run these commands?" once the plan is shown, after the guards question, while the config on disk sets `checks.stop` or format-on-edit's `commands` for a module that is selected, or left out while the lock still owns its hook: a test whose config has either answers it.
- render-tapes installs the CLI and runs VHS; to check a tape against its rules only, import `tapeProblems` from `scripts/tape-rules.mjs` with the tape's text and fixture.
- guard-bash asks before any `git -c <key>=<value>` whose key is off M4's safe allowlist, `core.fsmonitor=false` included, so a skill's `allowed-tools` entry with such a `-c` still prompts wherever safety is installed: check a new pre-approved command against the built guard-bash with a payload file.
- Test files have lint's 300-line cap too: put a new hook test in the file for its concern, as `format-on-edit-files.test.ts` holds the files the hook acts on, with shared helpers in a `*-helpers.ts`.
- commitlint refuses a subject that starts with a capital letter after the type, such as `fix(cli): Next steps ...`; the lint-staged run before it still restages, so commit again with the subject reworded.
- A wait in a tape must not match text the tape typed, or the echoed prompt satisfies it at once: put a comma right after a marker the reply must continue, as `DONE:,`; `test/render-tapes.test.ts` holds every tape to it.
- The warm-init timing in `npm run context` swings with machine load: 374–873 ms in most of review round 3's runs, 1,634 ms once, against 2,000.

- `spawnSync` waits for a program's output pipes to close, not for the program: a process it leaves holding them makes the call wait out its timeout. `runProgram` then keeps the program's exit status (review round 4).
- Homebrew's Node.js loads `libnode` through `@rpath`, so a copy of `process.execPath` cannot start on macOS: stand in for Windows' `ruff.exe` with a `#!/bin/sh` script that execs node.
- A tape that types right after `Wait+Screen /Next steps/` can echo keys into init's output before its process exits: keep a short `Sleep` there.
- init asks git about tracked tool folders through `CliContext.trackedFolders`: an in-process init test stubs it with `InitSetup.shipped` (none by default, null for no answer from git), and a test that builds a `Planned` by hand gives it `shipped: { folders: [], tracked: true }`.
- `schema/lock.schema.json` embeds `UNPRINTABLE`: run `npm run schema` after changing it, or `schema:check` fails.
- A `\u` escape typed into an Edit or Write call can land in the file as the character itself: build invisible characters in tests with `String.fromCodePoint`, and check a file's bytes with `od -c`.
- `test/hook-stop-check.test.ts` is at about 296 of lint's 300 lines after review round 6; the runner's own tests are in `test/stop-check-runner.test.ts`, and a new hook test goes in a file of its own.
- `runInit` runs init with a fresh empty home folder unless the test passes `home`, so a test of the sandbox warning writes `.claude/settings.json` under the home it passes, and this repository's own `.claude/settings.json` never reaches init tests.

# Feature: v0.1-m4-safety

Status: done, ready for review and the PR | Branch: feat/v0.1-m4-safety

## Goal

v0.1 milestone M4 (issues #30, #31, #32, #33): the safety layer the kit installs into users' projects. The hook runtime in `src/hooks/runtime` (ADR-0015's contract), guard-bash and guard-secrets ported faithfully from this repo's hardened `.claude/hooks/` to strict TypeScript and bundled by tsdown, and the safety module that registers both guards in exec form and writes the six native deny rules. Done means every acceptance criterion in the four issues holds (an ADR or a recorded decision wins where an issue differs, and each such case is explained here), a second init plans zero changes, and `npm run check` is green.

- 2026-10-10: Each hook's logic lives under `src/hooks/runtime/`: the shared runtime at its top, guard-bash's tokenizer in `shell/` and its rules in `bash/`, guard-secrets in `secrets/`. A hook entry (`src/hooks/<name>.ts`) is two lines: `launch(name, () => import('./runtime/…'))`. Why: lint lets an entry import only `node:` built-ins and `./runtime/` (ADR-0011, ADR-0015), and tsdown builds only the top-level files of `src/hooks`.

- 2026-10-10: guard-bash is a faithful port: zero verdict differences from the reference over all 484 strings in `test/guards.test.ts` and `test/guard-bash-review.test.ts`, with the repo policies on (a scratch differential run). The kit's own tables port both suites and run in-process; `test/hook-bundles.test.ts` runs the real bundles.
- 2026-10-10: guard-bash's bundle budget is 120 kB (`budgets.json` `hookBundle.overrides`, check-package reads it), with a note in ADR-0017 and a pointer in ADR-0015; every other hook keeps 30 kB. Bundles stay unminified. Why: the port bundles to 109.7 kB as built, 102.3 kB without comments, 79.2 kB minified with names and 54.0 kB fully minified, and the reference itself to 91.6 kB, so 30 kB cannot be met without dropping hardened rules, which the brief forbids. Minifying saved no latency (p50 36 ms, p95 43 ms either way), while a readable bundle keeps the file committed in users' repos auditable and its update diffs reviewable. Pending the owner's sign-off (Open questions).
- 2026-10-10: guard-bash's repo policies are safety options, off by default (ADR-0015): `blockAiAttribution` (the reference's AI-attribution deny) and `blockNoVerify` (`--no-verify`, `commit -n`, `HUSKY=0`, and `core.hooksPath` through `-c`, `git config` or `GIT_CONFIG_*`). #31's "extra user patterns" are `denyCommands`: a program and words, matched on parsed commands (the words in order among the arguments), through wrappers and chains. Why: ADR-0015 forbids judging regexes over raw text; a parsed match cannot be dodged by quoting or chaining.
- 2026-10-10: Hooks read their module's options from `<state dir>/config.json` at run time (`readModuleOptions`), only as a regular file inside the project, at most 256 kB, a leading byte-order mark stripped. guard-bash asks when that config is unreadable or an option has the wrong type. Why: options are user intent in the committed config (ADR-0014), the stop check (M6) will read `checks.stop` the same way, and a guard that silently dropped a deny option would fail open.
- 2026-10-10: guard-bash asks when the payload names no command (the reference allowed it) and when stdin is not a JSON object (#31 comment). Why: ADR-0015 fails both guards closed on anything they cannot read.
- 2026-10-10: #31's exec-capable git rule (`bash/git-config.ts`): ask on `-c`, `--config-env`, `git config <key> <value>`, `git clone -c`, and the variables `GIT_EXTERNAL_DIFF`, `GIT_SSH_COMMAND`, `GIT_SSH`, `GIT_PAGER`, `GIT_EDITOR`, `GIT_SEQUENCE_EDITOR`, `GIT_ASKPASS`, `GIT_PROXY_COMMAND`, `GIT_EXEC_PATH`, `GIT_TEMPLATE_DIR`, `GIT_CONFIG`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT` and `GIT_CONFIG_KEY_n`/`VALUE_n`, set on any command or exported, since any program may start git. Safe: a short key allowlist (identity, line endings, quotepath, abbrev, gpgsign, pull/merge/push/fetch defaults, `log.decorate`, `diff.renames`, `status.showuntrackedfiles`, `rebase.autostash`, `gc.auto`, `color.*`, `advice.*`) and a pager or editor that runs nothing else (`cat` or empty for a pager, `true` or `:` for an editor). Also asks on `--exec-path=<dir>`, `--upload-pack`, `--receive-pack`, `--exec` and `clone -u`, which name a program git runs. Why: the R3 security review; the value allowlist keeps `GIT_EDITOR=true git rebase --continue` and `GIT_PAGER=cat git log`, which agents run constantly, from prompting. A value from an expansion on a safe key no longer asks (the reference asked on any expanded `-c`), since an unsafe key asks anyway.
- 2026-10-10: #31's parser fixes: `$((…))` is arithmetic when bash would read it so (its `))` closes it; a lone `)` first makes it `$( (…) )`), and its inner substitutions are still parsed and judged; `NAME=(…)` and `NAME+=(…)` are arrays of words, their substitutions still judged. Windows paths: a drive (`C:\`, `C:/`, Git Bash's `/c/`, Cygwin's `/cygdrive/c/`) is normalised for home, the project and each target, and a path on a drive is also judged as if the drive were the root, so `rm -rf /c/Users/me` and `/c/Windows` are denied; a single-letter top folder counts as a drive root on every OS. The project folder has one source (`projectDirOf`: `CLAUDE_PROJECT_DIR` unless empty, else the working folder). Readability: one copy of each helper, plain arrays instead of `.split(' ')`, a function map instead of method-name dispatch, no increment inside an expression.
- 2026-10-10: `git checkout <file>` checks the file against the payload's `cwd` (else the project), not the hook process's working folder as the reference did. Why: guard-secrets resolves relative paths against `cwd` too (R3), and Claude may have changed folders.
- 2026-10-10: guard-secrets shares core's pattern list (`secretKinds` in `src/core/secrets.ts`, which said #32 would give both one list), and its reasons name the rule and the file (relative to the project for display only, forward slashes, control and bidi characters escaped), never the value. Everything else is the reference: pragma only on lines on disk (also under legacy slugs), replay on the real path wherever it is, `.env` names on the given and the real path, `cwd` resolution, `O_NOFOLLOW | O_NONBLOCK` after `lstat`, 1 MB caps, 50-million-character replay work counted as the text grows, asks on unresolvable targets.
- 2026-10-10: #32's high-entropy rule lives in core's `secretKinds`, so guard-secrets and the renderer share it: a name ending in `_KEY`, `_SECRET`, `_TOKEN` (or `-`) or in `PASSWORD`, then `=`, `:` or `:=`, then a value of token characters with a letter and a digit, no placeholder word (`example`, `test`, `your`, `here`, …), and at least 20 characters at 3.5 bits per character, or 32 hex characters at 3 bits. The regex starts only where a name starts and the value run ends at the first non-token character, so a scan stays linear. Why: the review found `API_KEY="<random>"` allowed; bare `key`, `integrity` and `checksum` names stay out so lockfile hashes pass.
- 2026-10-10: Hook state (no M4 hook writes any yet) goes only to `<state dir>/local/`: real folders inside the project, created 0700 with `local/.gitignore` of `*` rewritten when it ignores less, files written 0600 through a temp file created `O_EXCL | O_NOFOLLOW` and renamed into place, so neither a symlink nor a hardlink at the name is written through; a refused write is returned for the hook to report. Programs run through `runProgram` (absolute path, argument array, `spawnSync` without a shell, never a `.cmd` or `.bat` shim), Node tools through `process.execPath`, and `findProgram` looks only in absolute PATH folders outside the project, as `git-state.ts` does. Why: ADR-0015's runtime contract; the temp-and-rename write closes the hardlink case the reference's `O_TRUNC` left open.
- 2026-10-10: `--self-test` runs each hook's embedded samples with the hook's own folder as the project, so a project's options cannot fail them (doctor and the e2e will run it). Each sample names its outcome (`allow`, `ask`, `deny`, `context`, `block`, `refuse`).
- 2026-10-10: Hook latency: `scripts/hook-latency.mjs` (`npm run latency`, in `npm run check`) runs each built hook as Claude Code does, 20 runs per sample payload after a warm-up, against `budgets.json` `hookLatency.p95Ms` (200). CI gates it with `--gate` in the ubuntu Package checks job and reports it in the install-smoke job on ubuntu, macOS and Windows; locally it reports. A built hook without sample payloads in the script fails it.

It warns about an entry that names nothing, with the names it takes. Why: the #33 comment; warning on every run would undo ADR-0014's "optOut silences the warning", and `ownable` is limited to entries the current manifest declares (ADR-0014).

The remaining gaps are in `docs/guards.md` Known limits.

Both cases are in `docs/guards.md` Known limits.
- 2026-10-10 (review round 1): Left as designed: `optOut` is warned about once per lock, not once per machine, so a teammate who clones a repo with a committed lock and optOut gets no warning (ADR-0014: optOut silences the warning; a per-machine warning would need state M4 does not write yet). `.env-local`, `.env_local`, `*.env`, inline interpreter code (`python3 -c`, `node -e`, `perl -e`) and GNU `parallel` stay out of the rules, as in the reference, and are listed in Known limits.
- 2026-10-10 (review round 2): guard-bash counts only what a command writes as touching the guard files: output redirects (`>`, `>>`, `>|`, `>&`, `&>`, `&>>`, `<>`, recorded by the tokenizer as `outputs`), the destination of `cp`, `ln`, `install` and `rsync` (the last operand, or `-t`), every argument of the other writers, and the starting folders of a `find` with `-delete` or an `-exec` that deletes, moves or changes files. Why: the round-2 review; `jq . < .claude/settings.json` and `cp .claude/settings.json /tmp/` asked with a wrong reason, `find .claude/hooks -delete` passed, and `cd .. && mv proj x` turned the guards off. Left as Known limits: a name filter aiming a delete from a folder above `.claude` (`find . -name '*.mjs' -delete`) and a recursive copy whose files overwrite them (`cp -r ../template/. .`), since judging either needs the file tree, not the command line.
- 2026-10-10 (review round 2): A committed config and lock that both opt out of a guard set up a teammate's copy without that guard and with no warning. Left as designed (round 1's decision, ADR-0014) and now listed in `docs/guards.md` Known limits.
- 2026-10-11 (review round 3): guard-bash also counts as writes `ln <target>` with one operand (it links `./<name>` into the current folder), rsync's space-separated option values (`-T`, `--backup-dir`, `--files-from` and the rest), and git's own writers: `git rm` without `--cached`, both sides of `git mv`, and `git stash -u` or `-a` (its paths, or the tree's `.claude` with none), each from the `-C` folder, with `:/` taken as the project. `git rm -r .` at the project's top asks as a removal of the project folder, whose reason now says "home or project folder", since home counts too. Why: the round-3 review found `git rm -r .claude`, `git mv .claude x` and `git stash -u` allowed, which turn both guards off like a plain `rm`.
- 2026-10-11 (review round 3): When the user changed an opted-out guard's registration, init keeps it (round 2) and now keeps the bundle it runs too: init plans once, finds the kept registrations (`skip` ops on opted-out hook keys) and plans again without their bundles among what optOut removes. Such an entry removes nothing, so init does not warn about it. Why: deleting the bundle left `node <missing>.mjs` failing before every Bash call. Rejected: warning that the registration should be deleted, which leaves the broken state in place until the user acts.
- 2026-10-11 (review round 3): Whole-disk erasers (`dd of=/dev/disk0`, `mkfs.*`, `diskutil eraseDisk`, `wipefs`, `fdisk`) and archives unpacked over the guard files (`tar -xf`, `unzip -o`) are Known limits, not rules. Why: judging PowerShell needs its own parser and matcher, and guard-bash has about 4 kB left under its 120 kB budget. The owner deferred `PowerShell(…)` deny rules to v0.2 (#87).

## Gotchas / don't try again

- A worktree-isolated agent's shell refuses compound commands it cannot verify: heredocs with braces, `&&` chains that name git in piped text, `time -p`, variables holding paths. Write scratch scripts with the Write tool and run them as plain commands; feed payloads from files. Any argument containing "git", such as `test/hook-guard-bash-git.test.ts` or a filter of `git-state`, gets the command refused too: run a broader test filter such as `test/hook-`.
- `parseCommands` lists a substitution's commands before the command that holds them: find a command by program, not by position.
- Brace positions count UTF-16 code units, so split a word with `split('')`, never `[...text]`.
- tsdown's `codeSplitting: false` refuses more than one entry per build; the scratch measurements need one config per hook.
- `npm run package -- --update` rewrites `scripts/package-files.txt` after a new published file (a hook bundle, a module template).
- A test kit read through `readKit(REPO_ROOT)` holds the real bundles; `KIT` from `test/init-helpers.ts` holds stand-ins. Golden and snapshot tests use `KIT`; anything that runs an installed hook uses `readKit`.
- Never run `rm -rf`, not even on a worktree, a build folder or a scratch folder (the maintainer, 2026-10-10). Leave cleanup to the tools that own a folder (tsdown's `dist/`, the tests' `tempDir`, the scripts' `mkdtemp` folders) or ask the maintainer.
- A test that puts a Windows path into a bash command must single-quote it, since Git Bash and guard-bash's tokenizer drop unquoted backslashes, and take it from `realpathSync.native`, since a Windows runner's temp path holds an 8.3 short name that only the native real path expands. The Windows CI job on PR #85 caught both.
- In a sandbox that cannot write `~/.npm`, every `test/check-package.test.ts` case fails with `npm pack` EPERM on `~/.npm/_cacache`, which is not a code failure. Run the check with `npm_config_cache` set to a writable temp folder.

Add the stop-check module to the full preset. Before Claude stops, its hook runs your test command when uncommitted work other than docs differs from the last commit and that set of changes has neither passed nor failed before, so work Claude commits before it stops is not checked; a failure goes back to Claude once for each set of changes, with the last lines of its output, each escaped, invisible format characters such as tag characters included, and quoted with `> ` under a header that says they are data, not instructions. It learns what changed from git, so it needs a git repository: where git cannot say, it runs nothing and says so on stderr, and `init` warns when it turns the check on in such a folder. It runs nothing until `checks.stop` is set in the module's options in `.archkeeper/config.json`: an interactive `init` shows the detected command (`npm run test` where package.json has a test script, whatever the package manager, else `pytest`), says that the check runs it without asking, and so whatever it collects in the folder, code Claude writes, clones or downloads included, and that the command must exit on its own, and sets it only when you say yes, the default being no, which it records as `[]` so it does not ask again; a scripted `init` sets it only with the new `--stop-check` flag. `init` proposes no test script that starts a watcher, such as `jest --watch`, `ng test` or `react-scripts test`, which would hold every stop until the timeout, and no npm command in a Yarn Plug'n'Play project, which installs no `node_modules` for npm to run the script from. While it is unset, `init`'s Next steps say the check is off and how to turn it on, offering `--stop-check` only where `init` finds a test command. Where the config `init` reads already sets `checks.stop`, as a cloned repository's may, `init` names the command under the plan, says to remove it unless you trust whoever wrote it, and, on a terminal, asks before it applies, defaulting to no, also while stop-check is left out but the hook `init` installed earlier stays, which Next steps then say still runs; `--stop-check` keeps such a command and says so when it is not the detected one. `init` warns and asks the same way when git tracks files in `node_modules` or `.venv`, where the hook would find the repository's own copies of the tools rather than yours, and when either folder exists where git cannot say, as in a copy downloaded without `.git`. npm runs only as `npm test` or `npm run <script>`, through npm's own JS entry with `--ignore-scripts`, so no pre- or post-script runs; any other command is a JS bin from `node_modules` or a program from `.venv` or PATH, never a shell, wrapper, package or task runner such as `npx`, `uv`, `pixi`, `poetry`, `tox` or `make`, and a command the hook cannot run is skipped with a one-time hint. `checks.stopTimeout` (seconds, default 300, at most 590) bounds a run: one that does not finish is killed and lets Claude stop, and one whose tests left a process holding its output, such as a server started in the background, still counts with its exit status once the timeout ends the wait. Where it cannot record a result, it lets Claude stop with a note that says how the run ended. The shared hook runtime got smaller, so every hook bundle shrank. With `.claude` linked to a folder outside the project, `init` with the full preset now refuses unless `stop-check` is left out as well.
